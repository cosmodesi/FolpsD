# Cross-Power Figure Set

Generated by:

```bash
/opt/anaconda3/envs/aaenv/bin/python docs/cross_power/make_cross_power_figures.py
```

The script uses the NumPy backend by setting `FOLPS_BACKEND=numpy` before
importing FOLPS. It uses the public linear spectrum `folps/inputpkT.txt`, the
public matrix cache
`folps/output_matrices/matrices_nfftlog128_Afull-True_use_TNS-False.npy`, and
the representative cosmology used by the repository examples:
`z=0.3`, `h=0.6711`, `Omega_m=0.3211636237981114`,
`f0=0.6880638641959066`, and `fnu=0.004453689063655854`.

The common calculation settings are `model="EFT"`, `damping=None`,
`A_full=True`, `use_TNS_model=False`, `IR_resummation=True`,
`ells=(0,2,4)`, `nmu=16`, `qpar=1`, and `qper=1`, except where a figure
explicitly changes one of these choices. The output grid contains 145 samples
from `k=0.01` to `0.30 h/Mpc`; the displayed range is usually limited to
`k <= 0.20 h/Mpc`.

All tracer parameter arrays are supplied at the public API boundary in the
prior-document convention,
`bias_scheme="priordoc"` and `bias_scheme_b="priordoc"`. The first four entries
are ordered as `b1, b2, bK2, btd`; the last eight entries are
`alpha0, alpha2, alpha4, ctilde, alphashot0, alphashot2, PshotP, X_FoG`.
The LRG-like tracer A and ELG-like tracer B values are illustrative and are
not DESI best fits.

The cross-spectrum nuisance vector is explicitly pair-level:
`alpha0_ab, alpha2_ab, alpha4_ab, ctilde_ab, alphashot0_ab, alphashot2_ab,
PshotP_ab, X_FoG_ab`, with `X_FoG_ab=0`. These values are chosen directly and
are not arithmetic or geometric averages of the two auto-spectrum nuisance
sets.

Important cautions:

- `P^{AB}=sqrt(P^{AA}P^{BB})` is exact only in a restrictive deterministic
  linear limit.
- Closeness to the geometric mean at one parameter point is a numerical
  observation, not an algebraic identity of the one-loop model.
- Cross EFT and stochastic terms are independent pair-level quantities.
- The FolpsD cross damping modes are alternative nuisance models: `single`
  uses one pair-level damping parameter, while `geometric` uses the two
  tracer-level damping parameters.
- Neither damping mode is claimed to be uniquely preferred by first principles;
  mocks and data should determine whether the extra tracer-level structure is
  useful.
- Values of `r(k,mu)` slightly above unity can result from independently chosen
  truncated EFT and stochastic parameters and do not automatically indicate a
  code failure.
- No DESI-internal measurements, covariances, or best-fit parameters are used.

## Figure 3

Filename: `figures/cross_geometric_mean_bias_dependence.pdf` and
`figures/cross_geometric_mean_bias_dependence.png`

Purpose: identify which controlled sectors generate the departure from the
geometric-mean diagnostic.

Parameters: one representative angular slice, `mu=0.5`. The first case uses a
local synthetic linear-only table built from the public FOLPS table schema:
the public linear spectrum and growth row are retained, all loop/EFT/stochastic
rows and IR sigmas are set to zero, and `IR_resummation=False`. Cases two
through four use the production loop table with auto and pair nuisance set to
zero and `IR_resummation=False`. The final case adds the explicit pair-level
EFT/stochastic vector while keeping auto nuisance zero, isolating that the pair
nuisance is not determined by the auto spectra.

Diagnostic shown: `r(k,mu=0.5)-1` for:
linear deterministic, matter/RSD loops with linear bias only, adding `b2`,
adding `bK2` and `btd`, and adding cross EFT/stochastic terms.

Script function: `make_cross_geometric_mean_bias_dependence`.

CSV: `tables/cross_geometric_mean_bias_dependence.csv`.

Caution: this is a diagnostic sector switch, not a separate production physics
implementation. The script does not duplicate the one-loop formulas; it calls
the public FOLPS pair API with controlled parameters.

## Figure 6

Filename: `figures/cross_damping_modes.pdf` and
`figures/cross_damping_modes.png`

Purpose: compare the two public FolpsD cross damping prescriptions.

Parameters: `model="FOLPSD"`, `damping="vdg"`, baseline prior-document tracer
and pair nuisance values with illustrative FoG choices
`X_FoG_A=0.30`, `X_FoG_B=6.00`, and `X_FoG_ab=1.20`.

Diagnostic shown: upper panels compare `kP_ell^{AB}` for `single` and
`geometric`; lower panels show
`(P_{ell,geometric}^{AB} - P_{ell,single}^{AB}) / P_{ell,single}^{AB}` with
robust masking where a denominator is too small.

Script function: `make_cross_damping_modes`.

CSV: `tables/cross_damping_modes.csv`, containing `k`, the single and
geometric multipoles for `ell=0,2,4`, and the corresponding fractional
differences.

Caution: `single` and `geometric` are alternative phenomenological nuisance
models. The first uses one pair-level damping parameter. The second uses the
two tracer-level damping parameters and ignores `X_FoG_ab`, which remains in
the cross nuisance vector for API compatibility. Mocks and data should decide
whether this extra tracer-level structure is useful.

## Optional A_full Comparison

The optional `cross_Afull_comparison` figure is omitted. The repository
currently contains the public production cache for `A_full=True` and
`use_TNS_model=False`, but not a matching `A_full=False` matrix file. The
figure script therefore avoids generating a new production matrix file or
changing the global `A_full_status` during the figure set.
