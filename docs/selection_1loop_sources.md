# One-loop LOS selection: sources, versions and recorded corrections

Companion to [`selection_1loop_equations.md`](selection_1loop_equations.md) and
[`selection_1loop_validation.md`](selection_1loop_validation.md). Nothing below is assumed
correct because it is published or because it is a reference implementation: every external
coefficient used by the code was re-derived by the kernel oracle (`folps/selection_kernels.py`)
and the external version is used only as a cross-check.

## 4. Recorded corrections and convention differences

1. **DJS Appendix F.7, η⁽³⁾ row (printed).** Printed: `μ² (2, 3/2, −1/2, 0, 0)/7`.
   Correct in DJS conventions (η⁽³⁾ = −fμ²G₃): `μ² (−2, 3/2, 1/2, 0, 0)/7`.
   Evidence: (i) oracle identification, residual 7e-15; (ii) collapsed-G₃ identity; (iii)
   DJS's own Appendix E.9; (iv) GeneralBiasPk `M13.jl` uses the corrected row; (v) the
   audit's toy-spectrum response at k = 0.4: corrected 3.82899e-4 vs printed 6.1788e-4
   (`dev/selection_audit/audit_results.json`). Test: `test_eta_row_correction_of_printed_F7`.
2. **DJS supplement `Anmp` vs our P22 tensor: sign of the u∥∂∥δ kernel.** The supplement's
   `Anmp` table (5 × 9 × 7 = 315 entries) agrees with our generated tensor to 4.5e-14 *only* when the sign
   of the u∥∂∥δ kernel is flipped (worst mismatch for every other single-kernel hypothesis,
   including identity, is O(10²); `dev/selection_audit/djs_supplement_comparison.json`).
   Our sign is fixed independently by the redshift-space map: with it, the ten-kernel
   contraction reproduces the standard Z₂ to 1e-14 for 300 random triangles
   (`test_quadratic_table_kernels_and_standard_Z2`). We therefore record this as a
   sign-convention difference (or typo) of the supplement, not a change to the model.
3. **Factor of two in P13.** DJS Eq. (3.18) is a single 1–3 contraction and Eq. (3.23)
   multiplies by two; the stored matrices (`CUBIC_M`) encode the single contraction and the
   code applies the factor once (checked against FolpsD's independent `M13` closed forms).
4. **Bare-bridge data placeholder (development history).** An interrupted generator run left
   `BRIDGE_D`/`BRIDGE_C` as zero placeholders in an intermediate data file; the closed-form
   test `test_bare_bridge_closed_form` caught it and the data were regenerated with the
   complete generator before the validation fixture was produced.
